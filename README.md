# Wi-Fi Radio Ai-Sheff

**English summary.** Wi-Fi Radio Ai-Sheff is an open-source, battery-powered push-to-talk walkie-talkie built on
an ESP32-S3 DevKitC-1 with an INMP441 I2S microphone, a MAX98357A I2S amplifier, a 12-LED WS2812 ring, a KY-040
volume knob and an 18650 cell in a 3D-printed case. Radios join any 2.4 GHz Wi-Fi network and talk to each other
through a small *bridge* — a Python 3 server (two files, standard library only) that runs on a cheap VPS
or an always-on PC (Linux, Windows, macOS) — so the range is limited only by where there is Wi-Fi with internet.
Speech is 16 kHz IMA ADPCM; every packet is signed and the audio is AES-128-CTR encrypted with a shared network key,
and the bridge forwards speech without decrypting it. Radios update their firmware over the air from the bridge,
cancel acoustic howling between radios in the same room, and are configured from a phone through their own
`RADIO-XXXX` access point. Two bridges can be linked so that each site keeps working on its own LAN.
The documentation and code comments are in Russian. License: MIT.

## Что это

Переносная рация «нажал — говоришь» на плате ESP32-S3. Кнопка одна: нажали, услышали короткое «пи-пи»,
говорите, отпустили — все остальные рации вашей сети вас услышали.

Рации не связываются друг с другом напрямую. Каждая подключается к обычному Wi-Fi — дома, в офисе, на раздаче
с телефона, — а речь передаёт через **мост**: маленькую программу на компьютере, который всегда включён и доступен
из интернета. Поэтому рации в разных городах слышат друг друга так же, как в соседних комнатах: **дальность
ограничена только тем, где есть Wi-Fi с интернетом**.

![Рация в корпусе: динамик за белым диском, вокруг светится кольцо; кнопка «говорить» на боку, регулятор громкости и выключатель сверху](docs/img/assembly.png)

Корпус 68 × 38 × 170 мм печатается на 3D-принтере без поддержек. Спереди — динамик за белым диском, сквозь
который светится кольцо из 12 светодиодов; на боку — кнопка «говорить»; сверху — регулятор громкости и выключатель;
снизу — гнездо зарядки USB-C.

## Возможности

- **Одна кнопка «говорить».** Говорит один человек за раз: мост отдаёт эфир тому, кто нажал первым, остальные
  при нажатии слышат «бу-бу-бу» («занято»). Залипшую кнопку мост отключает через 90 секунд.
- **Рации в разных Wi-Fi-сетях** — дом, офис, склад, дача, раздача с телефона. Рация запоминает до трёх сетей
  и подключается к той, что ловит лучше. Нужен Wi-Fi 2,4 ГГц: сети 5 ГГц ESP32-S3 не видит.
- **Шифрование ключом сети.** Ключ сети — общий пароль всех ваших раций и мостов, строка вида
  `XXXX-XXXX-XXXX-XXXX`. Каждый пакет подписан этим ключом, речь зашифрована (AES-128). Чужая рация или случайный
  сканер из интернета в эфир не попадут. Мост речь не расшифровывает — только пересылает.
- **Обновление прошивки по воздуху через мост.** Положили новый файл прошивки в папку моста — каждая рация,
  простояв 20 секунд без разговоров, скачает его, сверит контрольную сумму (sha256 — «отпечаток» файла) и только
  тогда перезапустится на новую версию. Трогать рации руками не нужно.
- **Защита от свиста.** Если две рации лежат рядом, звук может пойти по кругу и засвистеть — как микрофон, поднесённый
  к колонке. Прошивка сама находит частоту свиста и вырезает её узким фильтром.
- **Индикация кольцом.** Кольцо вокруг динамика показывает связь, кто говорит, громкость, заряд и ход обновления.
  Что значит каждый цвет — в таблице [«Цвета кольца»](docs/TROUBLESHOOTING.md#цвета-кольца).
- **Оценка заряда** аккумулятора 18650: шкала на кольце, сигнал «пора на зарядку», процент на странице рации и на
  странице моста. Просадки напряжения во время разговора не дают ложных тревог.
- **Настройка с телефона.** Новая рация открывает свою точку доступа Wi-Fi `RADIO-XXXX`. Подключились к ней
  телефоном — страница настройки открывается сама, как в гостинице: Wi-Fi, адрес моста, ключ сети, имя рации,
  громкость, яркость.
- **Страница моста:** какие рации в сети, у кого сколько заряда, кто сейчас говорит, журнал событий. Мост сам
  подсказывает неисправности: «в передаче одна тишина — проверьте микрофон», «не тот ключ сети?».
- **Мост — программа на Python** без сторонних библиотек (два файла: `walkie_hub.py` и `wt_proto.py`): работает
  на Linux, Windows и macOS. Есть готовые
  установщики службы для Linux (systemd, с самопроверкой раз в 2 минуты) и для Windows (Планировщик заданий).
- **Звук:** 16 кГц, сжатие IMA ADPCM 4 бита — около 86 кбит/с на одного говорящего, хватает и мобильного интернета.
  Приёмник копит 60–160 мс речи, чтобы сгладить рывки сети.

## Как это работает

Рация шлёт речь кусочками по 20 мс в мост. Мост решает, кто сейчас в эфире, и пересылает речь всем остальным
рациям. Связь всегда начинает рация, поэтому настраивать роутеры у раций не нужно — входящие порты должны быть
открыты только у моста: **UDP 47000** (связь с рациями) и **TCP 47080** (страница состояния и раздача прошивки).

```
   Дом                                                               Офис
 ┌─────────┐  Wi-Fi  ┌────────┐                     ┌────────┐  Wi-Fi  ┌─────────┐
 │ рация 1 │ ~~~~~~~ │ роутер │───┐             ┌───│ роутер │ ~~~~~~~ │ рация 2 │
 └─────────┘         └────────┘   │  интернет   │   └────────┘         └─────────┘
                                  ▼             ▼
                            ┌───────────────────────┐
                            │         МОСТ          │  облачный сервер
                            │  UDP 47000 — рации    │  или компьютер
                            │  TCP 47080 — страница │  с постоянным адресом
                            └───────────────────────┘
                                          ▲
 ┌─────────┐  раздача Wi-Fi  ┌─────────┐  │
 │ рация 3 │ ~~~~~~~~~~~~~~~ │ телефон │──┘
 └─────────┘                 └─────────┘
```

Что происходит при нажатии кнопки:

1. Рация спрашивает мост: «можно говорить?». Эфир свободен — звучит «пи-пи», кольцо горит красным.
   Кто-то уже говорит — «бу-бу-бу», ждите.
2. Пока кнопка нажата, речь уходит в мост сжатой и зашифрованной.
3. Остальные рации играют её с небольшим запасом против рывков сети; их кольцо «пляшет» зелёным в такт голосу.
4. Отпустили кнопку — у остальных короткое «ти-ду»: передача закончена.

### Без облака

Мост можно поставить на компьютер в своей сети. Если поле «Адрес моста» в рации оставить пустым, рация сама найдёт
мост в своей сети широковещательным запросом (пакетом «всем в этой сети»).

```
 ┌───────┐  Wi-Fi  ┌────────┐     ┌──────────────┐
 │ рации │ ~~~~~~~ │ роутер │─────│ ПК с мостом  │    поле «Адрес моста» в рациях — пустое
 └───────┘         └────────┘     └──────────────┘
```

Если мест несколько, у каждого может быть свой мост, а мосты связываются между собой (поле `peers` в настройках
моста). Мостам нужно видеть друг друга по UDP 47000 — через интернет или через VPN (например, Tailscale или
WireGuard). Плюс такой схемы: внутри одного места рации говорят друг с другом даже при упавшем интернете.

```
 рации ~~~ [ мост «Дом» ] ◄═════ peers: интернет или VPN ═════► [ мост «Офис» ] ~~~ рации
```

Как выбрать и поднять мост — [docs/BRIDGE.md](docs/BRIDGE.md). Формат пакетов — [docs/protocol.md](docs/protocol.md).

## Что понадобится

| Деталь | Зачем |
|---|---|
| Плата ESP32-S3-DevKitC-1 N16R8 (или клон YD-ESP32-S3) | «мозг» рации и Wi-Fi |
| Микрофон INMP441 (цифровой, I2S) | голос |
| Усилитель MAX98357A (цифровой, I2S, 3 Вт) | усиливает звук для динамика |
| Динамик 8 Ом, 3 Вт, 32 × 32 мм | звук |
| Кольцо WS2812B на 12 светодиодов, Ø 50 мм | индикация |
| Регулятор KY-040 (вращающийся энкодер с кнопкой) | громкость; нажатие — выключить звук |
| Кнопка 16 мм (антивандальная) | «говорить» |
| Микротумблер | включение |
| Аккумулятор 18650 и держатель к нему | питание |
| Модуль заряда USB-C 5 В 2 А (типа «Power Bank Mini») | заряжает аккумулятор и даёт 5 В |
| Два резистора 100 кОм, диод 1N4007, две клеммы на 5 проводов, провода «мама-мама», термоусадка, саморезы 3 мм | делитель для измерения заряда, питание кольца, сборка |
| Корпус: ≈ 140 г PLA и белый диск динамика | печать на 3D-принтере, ≈ 6 ч |

**Цена одной рации — около 4 200 ₽** за детали и пластик, если собирать сразу три (одна рация отдельно — около
4 500 ₽: часть деталей продаётся наборами). Цены российских магазинов на сентябрь 2026. Точный список с количеством,
примерами «где можно купить» и размерами саморезов — в [docs/BUILD.md](docs/BUILD.md).

Ещё понадобятся паяльник, мультиметр (сильно упрощает поиск неисправностей), кабель USB-C **с передачей данных**
и компьютер, который будет мостом: недорогой облачный сервер или домашний ПК, который всегда включён.

Время работы от одного 18650 — по расчёту около 15 часов (на деле не измерялось).

## Разработка

Проверки — без железа, около 30 секунд:

```bash
python3 -m unittest discover -s tests
```

Что проверяется (21 проверка): мост с «программными рациями» на настоящих UDP-сокетах — эфир, «занято», тишина,
отключение залипшей кнопки, чужой ключ, раздача прошивки, речь через два связанных моста, одновременное нажатие
в двух местах; шифр AES по эталонным векторам, подпись пакетов; совпадение констант протокола в прошивке и мосте.
Переносимые части прошивки (сжатие речи, буфер приёма, оценка заряда, защита от свиста) собираются компилятором
компьютера и проверяются своими тестами, а сжатие речи ещё и сверяется с эталоном на Python. Для этого нужен
`clang++` или `g++`, без них эти проверки пропускаются.

Сборка прошивки (нужен [arduino-cli](https://arduino.github.io/arduino-cli/); ядро esp32 3.3.12 скрипт поставит
сам):

```bash
tools/build_firmware.sh
```

Плата в сборке — «ESP32S3 Dev Module», флеш 4 МБ, разметка Minimal SPIFFS (два места под прошивку — нужно для
обновления по воздуху), PSRAM выключена, USB в режиме Hardware CDC. Подходит и платам с флешем 16 МБ.
Итог — в `firmware/dist/`.

Выпустить новую версию для всех раций:

1. Увеличьте `FW_VERSION` в [firmware/walkie/config.h](firmware/walkie/config.h) — мост раздаёт прошивку только
   с бо́льшим номером.
2. Соберите: `tools/build_firmware.sh`.
3. Скопируйте `firmware/dist/walkie.bin` и `firmware/dist/walkie.json` в папку `firmware/` рядом с `hub.json`
   на мосту. Мост подхватит их сам за 10 секунд — подробнее в [docs/BRIDGE.md](docs/BRIDGE.md).

Правила для тех, кто правит код:

- Протокол описан в двух местах — [firmware/walkie/protocol.h](firmware/walkie/protocol.h) и
  [hub/wt_proto.py](hub/wt_proto.py); менять их вместе (и описание в [docs/protocol.md](docs/protocol.md)),
  `tests/test_parity.py` сверяет константы.
- Сборка идёт без ctags, поэтому в `walkie.ino` функции объявляются **до** использования.
- Комментарии в коде — на русском.
